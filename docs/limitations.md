# Ограничения мессенджеров

Три пункта исходного задания упираются в ограничения Telegram и Viber, а не в
код бота. Здесь — что именно нельзя, почему, и как FotoHu себя ведёт.

---

## 1. Удаление из чата: Telegram — максимум 48 часов

**Правило Telegram:** бот может удалить сообщение, только если оно отправлено
менее 48 часов назад. Это ограничение сервера Telegram; его не обходит ни
собственный Bot API сервер, ни какие-либо права администратора.

Что бот **может**: удалять входящие сообщения в приватных чатах, свои исходящие
сообщения, и до 100 сообщений за один вызов (`deleteMessages`).

**Как ведёт себя FotoHu**

- `purge_after_hours` настраивается в диапазоне 0…47, по умолчанию **1 час**
  после подтверждённой загрузки.
- Значения ≥ 48 принимаются, но админка сразу предупреждает, что Telegram их
  отклонит.
- Сообщения, которым уже больше 48 часов, **не отправляются в API вообще** —
  бессмысленный вызов заменяется записью `purge_error`, видимой в разделе
  «📊 Статус».

**Почему это не мешает задаче.** Требование было «чтобы снимки не хранились в
самом мессенджере». Оно выполняется: снимок уходит из чата почти сразу после
того, как копия проверена в облаке. Не выполняется только буквальная формулировка
«через любую настроенную дату» — для дат дальше двух суток такого API не
существует.

**Что не помогает.** Пользовательский аккаунт через MTProto (Telethon/Pyrogram)
умеет удалять свои сообщения без ограничения по времени — но только в своих
чатах. В приватный чат другого человека с ботом он попасть не может, поэтому для
семейного бота это не выход.

---

## 2. Удаление из чата: Viber — невозможно

Весь публичный REST Bot API Viber состоит из:

`set_webhook`, `get_account_info`, `get_user_details`, `get_online`,
`send_message`, `post` (для публичных аккаунтов).

**Метода удаления сообщения в нём нет.** Не «есть с ограничениями» — его нет
вообще.

**Как ведёт себя FotoHu.** Адаптер Viber объявляет `supports_deletion = False`.
Воркер очистки помечает такие записи один раз и больше к ним не возвращается,
а админка пишет «Viber: недоступно». Опционально можно включить напоминание
пользователю удалить снимок вручную (`viber_purge_reminder`, по умолчанию
выключено).

**Практический вывод.** Если очистка переписки важна — основным мессенджером
стоит сделать Telegram, а Viber использовать как дополнительный канал приёма.

## 3. Размер файла: Telegram отдаёт ботам до 20 МБ

Публичный Bot API не даёт боту скачать файл больше 20 МБ, даже если отправитель
с Telegram Premium загрузил 4 ГБ.

**Решение:** собственный Bot API сервер (`telegram-bot-api`) — предел 2 ГБ, и
вместо URL он возвращает **путь на локальном диске**, так что файл даже не
приходится качать повторно.

```bash
# получить api_id и api_hash на https://my.telegram.org/apps, положить в .env
docker compose --profile local-api up -d
```

и раскомментировать в `.env`:

```
TELEGRAM_API_BASE=http://telegram-bot-api:8081
TELEGRAM_API_LOCAL_MODE=true
```

Без этого бот на файле > 20 МБ отвечает понятным сообщением, а не молчаливой
ошибкой.

У Viber предел приёма файла — 200 МБ, отдельного сервера не требуется.

## 4. Качество: пережатое мессенджером не восстановить

Telegram пережимает `photo` и Viber пережимает `picture` **на своих серверах**.
До бота доезжает уже сжатая копия без EXIF; оригинал остаётся только на телефоне
отправителя. Никакой API не вернёт исходные байты.

**Единственный способ** сохранить оригинал — отправить снимок **файлом**
(`document` в Telegram, `file` в Viber). Тогда байты не трогает никто.

**Как ведёт себя FotoHu.** По умолчанию сжатые снимки отклоняются с подсказкой
`/howto`. Политику можно сменить в «🎚 Качество»:

| Политика | Поведение |
|---|---|
| `reject` (по умолчанию) | не сохранять, объяснить как слать файлом |
| `save_marked` | сохранить в подпапку `_compressed` |
| `save` | сохранять наравне с оригиналами |

## 5. Проверка целостности: что доступно у какого провайдера

FotoHu считает SHA-256, SHA-1 и MD5 одним проходом при скачивании и сверяет с
тем, что вернуло облако.

| Провайдер | Что возвращает | Проверка |
|---|---|---|
| Google Drive | `md5Checksum` | ✅ побайтная (MD5) |
| OneDrive Personal | `sha1Hash`, иногда `sha256Hash` | ✅ побайтная (SHA-1/SHA-256) |
| OneDrive for Business | только `quickXorHash` | ⚠️ сверяется лишь размер |
| rclone | зависит от remote (`--hash`) | ✅ если remote умеет |
| Локальная папка | считаем сами | ✅ SHA-256 |

`quickXorHash` — нестандартный алгоритм Microsoft; реализовывать его вручную ради
одного случая рискованнее, чем честно показать «размер совпал, побайтовая сверка
недоступна». Именно так и пишет бот в подтверждении.
